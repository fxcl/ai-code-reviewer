# Contributing to ai-code-reviewer

Thanks for your interest in contributing! This guide covers the dev setup, the repo layout, and the bar every change has to clear before it merges.

## Prerequisites

- **Node.js >= 20** (the Action runs on the `node20` runtime).
- **pnpm 11+** — this is a pnpm workspaces monorepo. Install with `corepack enable` (the pinned version is in `packageManager`).

## Getting started

```bash
git clone https://github.com/fxcl/ai-code-reviewer.git
cd ai-code-reviewer
pnpm install
```

## Repository layout

The engine is split into three packages so the core stays platform-agnostic and reusable (a future CLI / GitHub App reuses `core` + `llm` unchanged):

| Package | Name | Responsibility |
|---------|------|----------------|
| `packages/llm` | `@acr/llm` | Provider abstraction + implementations (Anthropic, OpenAI, Ollama, OpenAI-compatible). Structured output, retries, timeouts. No GitHub or env dependencies. |
| `packages/core` | `@acr/core` | Platform-agnostic review engine: diff parsing, chunking, prompt building, response parsing, finding filtering, summary rendering. Pure logic, no I/O. |
| `packages/action` | `@acr/action` | The GitHub Action adapter (the only entry point): reads inputs, talks to Octokit, orchestrates `core`, posts the review. Bundled to `dist/index.js` with esbuild. |

`docs/DESIGN.md` is the single source of truth for architecture and behavior; `docs/PLAN.md` is the task breakdown. Read the relevant section before changing behavior — **any decision change updates the docs first, then the code.**

## Development workflow

Run these from the repo root:

```bash
pnpm typecheck        # tsc --noEmit across every package (zero errors)
pnpm lint             # eslint . --max-warnings 0 (zero warnings)
pnpm test             # vitest across every package, with coverage
pnpm build:action     # bundle packages/action → dist/index.js
```

Work on a single package with a filter:

```bash
pnpm --filter @acr/core test
pnpm --filter @acr/llm typecheck
```

### The bar for every change

- **Tests pass with ≥ 80% coverage** (lines, statements, functions, branches). Coverage thresholds are enforced by vitest — a drop below 80% fails the build.
- **Zero lint warnings.** `pnpm lint` runs with `--max-warnings 0`; a warning is a failure. Fix the root cause, don't suppress it.
- **Zero type errors** (`pnpm typecheck`).
- **`dist/` is fresh.** If you touch `packages/action`, run `pnpm build:action` and commit the updated `dist/index.js` — CI verifies it matches the source.

### Test-driven development

We work TDD: **RED → GREEN → refactor.** Write a failing test that captures the desired behavior, make it pass with the smallest change, then refactor. HTTP is mocked in tests (`vi.stubGlobal('fetch', …)`) — no real network calls.

### Coding conventions

- Code, comments, and test names are in **English** (this is an open-source, international project).
- Prefer immutability — create new objects rather than mutating; use `readonly`.
- Keep files under ~800 lines, functions under ~50 lines, nesting under 4 levels.
- Handle errors explicitly; validate input at system boundaries. Never swallow errors silently.
- Naming: `camelCase` for variables/functions, `PascalCase` for types, `UPPER_SNAKE_CASE` for constants.
- **Never commit secrets.** API keys only ever come from GitHub secrets at runtime.

## Commit messages

Use the format `<type>: <description>`, where `<type>` is one of:

`feat` · `fix` · `refactor` · `docs` · `test` · `chore` · `perf` · `ci`

Examples:

```
feat: add Ollama provider
fix: anchor findings to the correct new-file line
docs: document the fork-PR secrets limitation
```

Keep commits focused and logically scoped. **Do not add co-author trailers or "Generated by" lines.**

## Pull requests

1. Branch off `main`.
2. Make your change TDD-style; keep the diff focused.
3. Run the full check locally before pushing:
   ```bash
   pnpm typecheck && pnpm lint && pnpm test && pnpm build:action
   ```
4. Open the PR with a clear description of what changed and why. Link any related issue.
